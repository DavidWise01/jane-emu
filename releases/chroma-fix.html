CHROMA FIX

ECK CHROMA WHEEL — from single hue slider to compound color model

THE PROBLEM

ECK currently defines CHROMA as:

{name:"CHROMA", hint:"HUE / visual phase", min:0, max:359, unit:"°"}

One slider. 360 steps. No structure. The hue wheel hides its own skeleton.

The correct definition is:

{{ r8!, g8!, b8!  ||  or6!, yl6!, pu6!, gr6!  ||  }}

Two levels. 7 named channels. 48 bits of address. The hue is DERIVED from these, not the other way around.

WHAT CHANGES IN ECK

The CHROMA def line in index.html line 268 becomes a compound object. The single slider becomes 7 sliders (3+4). The hue sent to the coupling engine is derived from these 7 channels, not stored directly.

// OLD:
{name:"CHROMA", hint:"HUE / visual phase", color:"#64f0af",
 min:0, max:359, unit:"°"}

// NEW:
{name:"CHROMA", hint:"COMPOUND / {{ r8!,g8!,b8! || or6!,yl6!,pu6!,gr6! || }}",
 color:"#64f0af",
 compound: true,
 primaries:   [{ch:"R",bits:8,max:255},{ch:"G",bits:8,max:255},{ch:"B",bits:8,max:255}],
 secondaries: [{ch:"OR",bits:6,max:63},{ch:"YL",bits:6,max:63},
               {ch:"PU",bits:6,max:63},{ch:"GR",bits:6,max:63}],
 // derived hue for coupling engine backward compat:
 deriveHue: function(p,s) {
   // compose: secondaries shift the primary mix
   var r = p[0] + ((s[0] - s[2]) << 2);  // OR pushes red, PU pulls
   var g = p[1] + ((s[3] - s[0]) << 2);  // GR pushes green, OR pulls
   var b = p[2] + ((s[2] - s[1]) << 2);  // PU pushes blue, YL pulls
   r = Math.max(0, Math.min(255, r));
   g = Math.max(0, Math.min(255, g));
   b = Math.max(0, Math.min(255, b));
   // RGB -> hue (standard conversion)
   var mx = Math.max(r,g,b), mn = Math.min(r,g,b), d = mx - mn, h = 0;
   if (d > 0) {
     if (mx === r) h = ((g - b) / d + 6) % 6;
     else if (mx === g) h = (b - r) / d + 2;
     else h = (r - g) / d + 4;
     h = Math.round(h * 60);
   }
   return { r:r, g:g, b:b, hue:h };
 }
}

The values[1] (hue degree) stays in the evidence ledger for backward compat — it becomes the DERIVED hue from the compound channels. The compound channels themselves get their own evidence fields (chroma_r, chroma_g, chroma_b, chroma_or, chroma_yl, chroma_pu, chroma_gr) in the sample record.

// sample() becomes:
function sample() {
  var composed = chromaDef.deriveHue(chromaPrimaries, chromaSecondaries);
  return {
    primitive: "observed-chrome-v2",
    position_deg: values[0],
    // compound chroma — the full state
    chroma_r: chromaPrimaries[0],
    chroma_g: chromaPrimaries[1],
    chroma_b: chromaPrimaries[2],
    chroma_or: chromaSecondaries[0],
    chroma_yl: chromaSecondaries[1],
    chroma_pu: chromaSecondaries[2],
    chroma_gr: chromaSecondaries[3],
    // backward compat: derived hue
    hue_deg: composed.hue,
    wavelength_nm: values[2],
    chronos_ms: values[3]
  };
}

The hue wheel is NOT a circle.
It is a 7-vertex ring with alternating depths.
3 deep (8-bit) + 4 shallow (6-bit).
The circle was always a projection.

TODDLER CORNER

Colors have a skeleton, like you do.

Your skeleton has big bones (arms, legs, spine) and small bones (fingers, toes). The big bones hold you up. The small bones let you do fiddly things.

Colors work the same way. Red, Green, Blue are the big bones — 8 bits each, 256 shades. Orange, Yellow, Purple, Green-between are the small bones — 6 bits each, 64 shades. The small ones sit between the big ones and tune the color.

The old model just had one dial that said "this much hue." That's like saying a person is "this tall" without mentioning they have a skeleton. The new model shows the bones.
