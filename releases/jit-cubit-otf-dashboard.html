Assessment — How Did It Work Out?

questionverdictevidence
Does the CUBIT learn on-the-fly?LIT969 weights updated every step through the i13 interpreter. No pre-training, no offline data. Learns from raw RAM bytes during live gameplay.
Does JIT compile per-request?LITImagination rollouts compile entire strategies (hold/chase/flee/sweep) on demand. The forward pass itself runs through the i13 interpreter — a program goes across, a value comes back. That is compilation at the speed of play.
Does OTF support JIT without importing context?LITOTF systems (PER, meta-ctrl, healing, momentum) operate only on weight arrays, TD errors, and reward signals. No OTF system reads RAM or knows what game is loaded. Only the stream crosses.
Is the crossing enforced?LITThe i13 IIFE boundary is the crossing. Internal state (i13W, i13T, i13PER) is IIFE-local. The main script accesses through the API object only. No definition crosses — only calls and values.
Does the stream carry only data?LITAcross the IIFE API: arrays of integers (features, weights, trainer state). No functions, no closures, no game-specific logic. PER entries store feature vectors and TD errors — data.
Does momentum bridge JIT and OTF?LITBuild 28 momentum is the first system that STRADDLES: it snapshots before the JIT learn pass and applies boost after. It sees both the program (weight deltas) and the correction (momentum EMA). This is the gap filled.
Can the system recover from forgetting?LITBuild 26 (self-healing) + Build 25 (meta-ctrl) + Build 27 (PER refresh): three overlapping recovery systems. Meta detects plateau → heal checks if rollback is warranted → refresh re-evaluates stale priorities. No single point of failure.
Is Q8 fixed-point sufficient?AMBERAll 28 builds verified in Node. No overflow observed. But: Q8 has 1/256≈0.004 resolution. Very small gradients (<0.004) truncate to zero. The ±1 integer clamp (Builds 28, core) is the patch — it forces movement when arithmetic says stop. Sufficient but not generous.
What is MISSING from the crossing?AMBERThe original 9-slot form had three witnesses: adversary, graveyard, tamper. This engine has 0 witnesses at the crossing. The ECK ledger exists in nes-agent-i13.html but does not audit the crossing itself — it audits the game events. No system verifies that the stream wasn't corrupted in transit.

Toddler Version — The Three Engines

Imagine you're playing a video game for the first time.

The JIT engine is your EYES and HANDS. It looks at the screen (RAM bytes), figures out what's happening (features), and decides which buttons to press (actions). It does this 60 times a second, every second, with no instructions. It's just-in-time — it figures out what to do right now, not ahead of time.

The CUBIT is your BRAIN. It's a tiny neural net — just 1215 numbers that get multiplied and added together. Those numbers are its "knowledge." When it starts, all the numbers are random, so it makes random moves. As it plays, the numbers change to make better moves. Everything is done in whole numbers (no decimals) because the brain runs on a very simple calculator (the i13 interpreter) that can only do integer math.

The OTF engine is your COACH. It watches the brain play and helps it learn better:
• When the brain does something good, the coach writes it on a flashcard (PER replay) so the brain can study it later
• When the brain gets stuck, the coach wiggles the difficulty knobs (meta-controller)
• When the brain forgets what it learned, the coach pulls out an old photo of the brain at its best and rebuilds it (self-healing)
• When the brain's learning is jittery, the coach smooths it out like rolling a ball downhill (momentum)
• The coach re-reads old flashcards to make sure the ones marked "hard" are still actually hard (PER refresh)

The STREAM is the HALLWAY between the eyes and the coach. Only numbers go through the hallway — no instructions, no shortcuts, no cheating. The eyes see the game and send numbers. The coach sees the numbers and fixes the brain. Neither one can see what the other one does. This is the crossing.

Open Questions — What The Board Cannot See

gapseveritywhere it matters
No crossing witnessHIGHThe stream between JIT and OTF is unaudited. A corrupted feature vector or a botched weight update crosses the gap and nothing catches it. The ECK ledger audits game events, not the crossing.
No curriculumMEDThe agent plays whatever ROM is loaded. No progression from easy to hard. The meta-controller adapts to what it sees but cannot choose what to see.
No multi-game transferMEDBrain state resets on ROM load. 28 builds of learning machinery and nothing survives across games. The shelf is rebuilt from scratch every time.
Q8 resolution floorLOWGradients below 1/256≈0.004 are invisible. The ±1 clamp is a patch, not a fix. Would matter more with deeper nets; at 1 hidden layer, usually OK.
Gate weights uncovered by momentumLOWBuild 28 momentum covers 969 MLP weights but not the 246 gate weights. Gates have their own update path, so this may be correct — or the gates may need their own momentum.
