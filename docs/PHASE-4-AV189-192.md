## AV-189 · Restore fallback ROM loading

### Observed source-level failure condition

The AV-173 instrumentation path attached an iframe load handler only after the optional NES source transformation succeeded. When any injected hook failed to match or the transformed NES script failed syntax validation, the fallback loaded the original NES cabinet but the parent never attached an equivalent ROM-ready handler. As a result, `ready` could remain false, and an early chosen cartridge could remain queued indefinitely.

### Fix

- Attach an original-cabinet iframe load listener in the fallback path.
- Set `ready` from the original cabinet's actual `romInput`, and replay the queued `.nes` file through the existing input event.
- Restore a fresh release fetch (`cache: 'no-store'`) to avoid reusing stale emulator HTML after GitHub Pages updates.
- Add `dashboard/av189_runtime.js`, an observation-only lifecycle log for booting, ready, fallback, ROM queue, ROM delivery, reported running frames and explicit errors. It records no ROM bytes and never presses controller buttons.
- Route the diagnostic module into existing **VERIFY** within the fixed **PLAY / LEARN / VERIFY** three-tool interface. Preserve the NES stage, input owner and learn tools.
- Add `tests/av189_runtime.test.cjs` to CI: checks fallback readiness wiring, queued-ROM replay, session isolation, fresh fetch, error states, and unchanged NES boot/handoff hooks.

### Browser acceptance remains outstanding

A passing CI regression proves that the programmatic fallback code is present and sound under the tested conditions. It does **not** prove that a real NES ROM has booted or that START reached the game. Phase 4 earns zero points until an actual browser session demonstrates those effects.

## AV-190 — Executable NES gameplay mechanics (2026-11-22)

The priority shifted from instrumentation toward actual input mechanics in the same emulator. Added `dashboard/av190_gameplay.js`, which produces deterministic UP, DOWN, LEFT, RIGHT, A, or B decisions when existing coaching has not already selected a button. These selections return through the pre-existing `chooseAction()` input path rather than creating another controller. The native title/menu START and game-over recovery paths retain precedence.

After completed emulator trial records, AV-190 updates per-button scores from the recorded region/pixel-change delta. All available actions receive deterministic exploration before scored reuse; movement and A/B presses remain eligible as the fixed priority order. Observed change is a *learning signal*, not proof of score, survival, or winning. The policy resets with cartridge/session or active-player changes and can be disabled with **GAMEPLAY ACTIONS** in the top toolbar.

Added `tests/av190_gameplay.test.cjs` and GitHub Actions gating for menu precedence, legal button selection, deterministic choices, completed-trial feedback, actor handoff, and native NES boot preservation. The three-tool layout remains Play, Learn and Verify, with the game canvas prioritized.

**Phase 4 acceptance remains 0%**: CI verifies policy selection and source wiring, not actual ROM gameplay or successful fighting/navigation. Next should test actual controller timing and goal-directed movement against a legal ROM, then fix observed gameplay errors.

## AV-192 — Gameplay timing and controlled Phase 4 freeze (2026-11-22)

- Added `dashboard/av192_timing.js`: adjusts **the duration of an action actually selected by AV-190**, bounded to 6–18 NES frames for directional movement and 3–12 frames for A/B attacks. START, menu actions, recovery, anticipation, counterattack, transfer and other existing policies retain their own timing overrides.
- A completed emulator trial with zero measurable screen change shortens the next hold for that action; a positive change may lengthen movement, while attacks remain brief. An explicitly observed loss can shorten exposure, but this outcome is **not** automatically inferred from screen changes.
- Each timing decision requires exact session, ROM, actor, action and source selection frame; invalid, stale or unrelated policies leave native timing unchanged. The NES remains a **single controller**.
- Added `tests/av192_timing.test.cjs` to the Pages workflow, covering bounds, exploration feedback, stale trials, actor transitions, lack of input override for START, and preservation of PLAY / LEARN / VERIFY.
- **Phase 4 final status: CLOSED / 0% verified live ROM acceptance.** AV-189–192 code was implemented and regression tested, but no actual licensed/test NES ROM session was observed in the browser. CI does not prove lives saved, game progress or controller delivery. Do not award unearned acceptance credit.
